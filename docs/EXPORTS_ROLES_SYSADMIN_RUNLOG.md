*Branch `feat/exports-roles-and-sysadmin`, 2026-08-03.*

Four quality-of-life tasks: PDF/Excel export polish, a Mac background-service

## 1. Export reporting polish

### 1a. PDF — columns overlapped and content was silently destroyed

`reports.to_pdf` / `to_pdf_sheets` — the renderer behind every `/reports/*`
download, the HOD purchase-request PDF, and the SME session / execution-plan /
overview documents — divided the page into **equal** column widths and then
hard-truncated content to fixed character counts (`[:18]` headers, `[:24]`
cells). Both halves were broken. Measured on a real receipts row:

| | |
|---|---|
| printable width | 277.0 mm across 9 columns = **30.8 mm each**, regardless of content |
| `Equipment_Description` "CUMICRETE PU MF 300 (1MM) COMPONENT C HARDENER RESIN" | needed 34.8 mm → **ran 4.1 mm into the next column** |
| `Supplier` "AL-JAZEERA INDUSTRIAL CHEMICALS TRADING EST" | needed 34.6 mm → **ran 3.8 mm over** |
| `Date` / `UOM` / `SAP_Code` | used 12.6 / 3.6 / 7.7 mm of their 30.8 mm — **~20 mm wasted each** |
| truncation loss | 28 characters of the description, 19 of the supplier |
| header damage | `Equipment_Description` → `Equipment_Descript` |

fpdf's `cell()` does not clip, so anything wider than its cell is simply drawn
on top of the neighbour — that is the overlap. The starving of long columns
while short ones hoarded space is what made it inevitable.

**Fix — `backend/api/pdf_tables.py`, one engine for every tabular PDF.**

1. **Max-min fair column widths.** A flat proportional scale was not enough: it
   pushed narrow columns *below* their own need, so `Date` wrapped to
   "2026-08-0 / 3" and `Site_ID` to "CNCE / C" to make room for a description
   that was going to wrap anyway. Water-filling instead — repeatedly offer each
   unsatisfied column an equal share of what is left, settle any column needing
   less than its share at exactly its need, and split the remainder among the
   genuinely wide ones. Widths sum to the printable width **exactly**.
2. **Real wrapping, nothing truncated.** fpdf2's own line-breaker via
   `dry_run`/`output="LINES"`, so the measured lines are the drawn lines,
   including character-level breaking of unbreakable tokens.
   *Gotcha found by measurement:* `multi_cell` silently reserves `pdf.c_margin`
   on **each** side of the box it is given, which `get_string_width` knows
   nothing about — a value measured as fitting still wrapped. The wrap width now
   hands that margin back.
3. **Font adapts to width** — 8 → 7 → 6 → 5.5 pt as columns grow.
4. **Atomic rows** with a repeating header and a guard against a row taller
   than a page.

Verified across six table shapes (9, 10, 11, 14 and 2 columns, plus a
400-character single-token cell): widths sum exactly, **worst overflow −0.55 mm
to −62 mm — i.e. everything fits, with margin to spare**, and the full
52-character description and its header both survive intact.

`exec_pdf.py` (HOD Executive Summary) already measured widths but still
`_fit`-truncated with `..`; it now delegates its tables to the same engine and
keeps its bespoke cover band and KPI boxes.

**Also found and fixed — the QR label sheets** (`documents.py`), which the audit
turned up on the way past:

* employee badge `Name` was drawn at a fixed 9 pt with `cell()` and cut at 32
  characters — a 32-char name measured 67.0 mm against a 62.7 mm sticker, so it
  **overflowed onto the neighbouring label**. Now shrinks 9 → 6.5 pt to fit.
* bin-label descriptions were cut at 60 characters. Now wrapped to the space
  actually available under the QR.

Both verified: full name preserved at 8 pt / 59.6 mm, full description in 2
lines / 59.5 mm, against 62.7 mm available.

### 1b. Excel — the premium template is now global

`sme_export_layouts.py` (xlsxwriter) had the good layout — GI logo, a
generated-at/by meta band, a merged navy title bar, coloured headers, framed
data. It was used by exactly three SME workbooks. Everything else —
**all `/reports/*`, the master-data exports, Man-Hours scorecards, the
Executive Summary, and the SME session/overview sheets** — came out of
`reports.to_xlsx`, which wrote a bare header row.

`backend/api/xlsx_style.py` implements the same geometry in **openpyxl** (what
those call sites already use, so nothing changes hands mid-pipeline), and
`to_xlsx` / `to_xlsx_sheets` now delegate to it:

```
rows 1-4   logo + right-aligned "Report Generated" / "Generated By"
row  5     merged title bar (scheme title_bg, white bold 13pt)
row  6     header row (scheme header_bg, white bold, centred, framed)
row  7+    data, framed, header frozen, autofilter, measured widths
```

Palette and scheme names are imported from `sme_export_layouts`, so the two
paths cannot drift apart.

**Deliberately NOT added: a GRAND TOTAL row.** The SME sheets carry one because
their numeric columns are all quantities in a known unit. A generic report's
numeric columns are things like `Days_Overdue` and `Unit_Price`; summing those
would print a confident wrong number.

Suites AX and AY read the old row-1 geometry and were updated to the new rows —
and strengthened while there, so AX now also asserts the logo, the meta band
and the title bar are present rather than only the column names.

## 2. Mac battery — `bin/power.sh`

The two named services turned out **not** to be the problem. Measured idle:

| | CPU | |
|---|---|---|
| Postgres | **0.0 %** | six parked backend processes, ~30 MB |
| cloudflared | **0.1 %** | one long-lived TLS connection |

The real drain was three **stale LaunchAgents from the pre-cutover stack**,
still loaded, whose programs were removed in the 2026-07-13 restructure:

* **`com.gi.whatsapp-worker`** — `KeepAlive{Crashed:true}` with
  `ThrottleInterval 30`, pointing at a `whatsapp_worker.py` that no longer
  exists. Measured live: the error log grew 410 bytes in 65 seconds =
  **2 Python interpreter launches per minute, ~2,880 a day**, every one failing
  instantly. Its log is **4.1 MB of the same line**, still being written today.
* `com.gi.streamlit`, `com.gi.locate-anything` — same shape; these hit launchd's
  crash-loop backoff in July and stopped, but remain loaded.

`bin/power.sh` covers both problems:

```bash
./bin/power.sh sleep     # stop Postgres + unload the cloudflared daemon
./bin/power.sh wake      # both back, verified against the live hostname
./bin/power.sh status    # what is up, and what it costs
./bin/power.sh reap      # unload + disable the dead legacy agents
./bin/power.sh restore   # put them back
```

* `sleep` refuses to pull Postgres out from under a running dev stack unless
  `--force`, asks for sudo **once up front** rather than mid-transition, and
  uses `bootout` + `disable` so the daemon stays down across a reboot.
* `wake` probes `https://gi.giinventory.com` with retries, because a registered
  connector is not the same as a routed hostname.
* `reap`/`restore` never delete a plist. The round trip was tested on
  `com.gi.locate-anything` and returned the machine to exactly its prior state.
* `bin/dev.sh` now points at `power.sh wake` when it finds the root daemon
  missing in `gi` mode, and its usage text explains the split.

**Nothing on the machine was left changed by this work** — the reap is the
operator's call, one command away.

## 3. Automated backups — `bin/backup_db.sh`

`com.gi.backup` has pointed at `host_setup/scripts/backup_db.sh` since it was
written, and that path stopped existing in the cutover. **It had failed silently
every night for 25 consecutive nights** — there were no local backups at all.

```bash
./bin/backup_db.sh              # snapshot now
./bin/backup_db.sh --list       # what is in .backups/
./bin/backup_db.sh --install    # daily at 02:00 (installed and verified)
./bin/backup_db.sh --restore F  # print the restore command
```

* Plain-SQL `pg_dump` of `gihub`, gzipped, into gitignored `.backups/`.
* Also copies the frozen legacy `gi_database.db` **read-only**, comparing its
  sha256 before and after so the script can prove it did not write to it.
* Writes to `.sql.part` first, then verifies the dump has pg_dump's end marker
  **and** at least one `CREATE TABLE` before promoting it — a dump that restores
  nothing is worse than no dump, because it looks like one.
* Retention prunes each kind independently (default 14).
* `--restore` **prints** the command rather than running it: restoring drops
  every table, which is the operator's decision to make with their eyes open.
* `--install` retires the broken `com.gi.backup` and installs
  `com.gi.hub-backup`.

**Verified by actually restoring.** The snapshot was loaded into a throwaway
database and compared against live: **74 tables**, `system_audit_log` 28,266
rows, users 8, `sme_inventory_seed` 32, `sme_recipe` 41, `sme_equipment` 85,
receipts 505, consumption 420 — all exact. Retention verified against 20
synthetic snapshots per kind (→ 14 + 14). The launchd job was kickstarted and
ran clean, **exit 0**.

## 4. The Auditor (view-only) role

New role `auditor`, **new-stack only** — `legacy/config.py` stays frozen at its
six roles.

**Level 3, deliberately.** Read scoping keys off the level ladder
(`SITE_SCOPE_MIN_LEVEL = 3`), and an unscoped account carries `site_id = ''`,
which the fail-closed scope helpers treat as *matches nothing*. A level-2
auditor would therefore have seen **nothing at all**. Level 3 buys global read
reach; it grants no write power, because every write is refused before the level
is ever consulted.

### The boundary: `backend/api/readonly.py`

ASGI middleware keyed on the **HTTP method**, not a dependency on each route.
That shape is the whole point: a per-endpoint annotation is only as good as the
developer's memory, and the one that gets forgotten **fails open** — the write
succeeds and nothing looks wrong. Keying on the method inverts the failure, so
an endpoint nobody has thought about yet is already closed.

Measured against the live route table: **143 mutating routes, 126 blocked**.
The 17 allowed are exhaustively documented — session lifecycle (`/auth/login`,
`/refresh`, `/logout`, `/login/2fa`), own-account (`/auth/2fa/*`,
`/auth/phone/*`), compute-only (`/sme/plan/cascade`, `/sme/plan/export`,
`/sme/export/rows`) and the AI read lanes that stream answers over POST.

Deliberately **not** allowed: `/reports/{key}/whatsapp` renders a report the
auditor may read but then *sends* it to a phone number; and
`/admin/users/*/reset-password` is a credential change, not self-service.

### The UI

* **`config/nav.tsx`** gained a `writes` flag on access rules. A page whose
  *purpose* is changing data — every entry form, Master Data CRUD, Bulk Import,
  Approvals, Procurement, the supervisor/warehouse portals, Users, Access
  Requests, Console — is unreachable for a view-only role. That removes the
  great majority of Edit/Upload/Sync/Delete controls **without touching a single
  page component**.
* **`useReadOnly()`** disables the remainder — controls on pages an auditor
  legitimately reads. Applied to Reports: Archive, WhatsApp, New schedule, Run
  now, the active toggle, and both Delete actions. Disabled with a tooltip
  rather than hidden, so the auditor can see the feature exists and that their
  role is why it is unavailable.
* **An axios interceptor** rejects a mutating request before it is sent and
  raises a toast, so a stray click gives an immediate legible refusal instead of
  a failed round trip. (Its rejection carries no `response`, so it is
  short-circuited ahead of the "API unreachable" diagnostics.)
* A **"View only"** tag sits in the header; `auditor` is in the registration,
  approval and admin role lists with its own colour.

### Verified live

Signed in as an auditor against the running stack:

* sidebar resolves to exactly Dashboard · Stock · Records (7 entities) ·
  Reports · Logistics→**Lining Coverage only** · Documents · Account. No Data
  Entry, Master Data, Admin, Warehouse, Supervisor, HOD, SME or Man-Hours.
* on all 20 report cards, Excel/PDF/CSV are enabled and Archive/WhatsApp are
  disabled with the explanatory tooltip.
* `GET /reports/stock?format=pdf` → **200, 130,847 bytes, valid PDF**.
* `POST /entry/receipts` → **403** *"your account is view-only (Auditor) — this
  action changes data and is not permitted"*.

### Suite BD (36 checks)

Rather than spot-checking endpoints, it **enumerates every mutating route the
app publishes** and requires each to be blocked or on the documented exception
list — so a new `@router.post` added next month fails this suite until someone
decides, deliberately, which side of the line it belongs on. The expected
allowlist is restated in the test independently of the module, so a change has
to be made twice.

It also pins the operator's explicit constraint: **admin, hod, logistics,
store_keeper, supervisor and warehouse_user each have 0 of 143 routes blocked**,
as do an absent, empty and nonsense role. Plus: a bad token is the route's 401
and never the guard's business; the guard runs before routing, so an auditor
probing an unknown path gets 403 rather than a 404 that maps the URL space; and
a revert check that fails if the middleware is ever unregistered.

## Follow-ups for the operator

1. **Run `./bin/power.sh reap`** — 2,880 failed Python launches a day are still
   happening. This is the single largest idle battery win and it is one command.
2. **The auditor cannot see the HOD group** (Executive Summary, Burn Rate,
   Low Stock, Purchase Requests, Document Library) or the SME Estimator, because
   those are exact-locked to `{hod, admin}` and an exact-lock is not a level. If
   an auditor should read them, add `'auditor'` to those `anyRole` lists — the
   write guard keeps them read-only regardless.
3. **`/feedback` submission is blocked** for an auditor, since it POSTs a row.
   Harmless, but if auditors should be able to file feedback, add its path to
   `_ALLOWED_EXACT`.
